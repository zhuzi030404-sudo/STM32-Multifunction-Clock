# 发布前检查

## 已整理

- 源码、CubeMX配置、CubeIDE工程配置和厂家许可文件放在同一目录。
- Debug编译产物、本机调试配置和工作区缓存不纳入版本管理。
- 不包含原开发目录的 `.launch` 日志路径、个人简历、原理图压缩包或上游原始代码压缩包。
- README说明功能、模块、限制和参考来源；界面示例明确标注为模拟图。

## 公开前仍需完成

1. 核实参考代码及点阵素材公开再分发的授权和适用条款。
2. 按实际获得的授权补齐相应许可证或授权说明，保留第三方原有声明。
3. 确定GitHub账户与仓库地址；建议仓库名 `STM32-Multifunction-Clock`。
4. 检查自己的Git提交姓名和邮箱：提交身份可能出现在公开历史里，可使用GitHub提供的隐私邮箱。
5. 补实物照片和演示，按实际验收结果更新验证记录。

授权尚未明确时，先在本地整理；如需个人远端备份，采用私有仓库，不等同于已经开源。

## 网页创建仓库

GitHub右上角 `+ → New repository`，填写仓库名与说明，选择合适可见性。上传本地已有仓库时，不在网页额外初始化另一份README或随意选择LICENSE，避免冲突或错误授权。

若不使用命令行，也可以通过GitHub Desktop添加此本地仓库、核对变更后提交并发布。Git是版本管理工具，GitHub是托管仓库的网站，二者不是同一个程序。
